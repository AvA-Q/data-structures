# 第 7 章 查找

> 依据视频原始音轨转写整理，保留原课程的讲解顺序、例子和结论。本文不显示音频时间段。

## 7.1 查找的基本概念

- 查找表：用于查找的数据集合。
- 关键字：能够标识数据元素的数据项。
- 查找：在查找表中寻找满足条件的数据元素。

查找结果：

- 查找成功。
- 查找失败。

### 平均查找长度

平均查找长度简称 `ASL`。

```text
ASL = Σ(Pi × Ci)
```

其中：

- `Pi`：查找第 `i` 个元素的概率。
- `Ci`：找到第 `i` 个元素所需的比较次数。

通常分别计算：

- 查找成功的 `ASL`。
- 查找失败的 `ASL`。

## 7.2 顺序查找

顺序查找：

> 从表的一端开始逐个比较。

适用：

- 顺序表。
- 链表。
- 有序表或无序表。

### 无序表

查找成功平均比较次数：

```text
(n + 1) / 2
```

时间复杂度：

```text
O(n)
```

### 有序表

如果查找失败，可以在当前元素已经大于或小于目标值时提前停止。

这样可以减少查找失败时的比较次数。

## 7.3 折半查找

折半查找也叫二分查找。

要求：

- 表必须有序。
- 必须支持随机访问，因此通常使用顺序表。

算法：

```text
mid = floor((low + high) / 2)
```

比较：

- 目标等于中间值：成功。
- 目标小于中间值：在左半区查找。
- 目标大于中间值：在右半区查找。

时间复杂度：

```text
O(log n)
```

折半查找过程可以用判定树描述。

注意：

> 链表不适合折半查找，因为无法快速访问中间位置。

## 7.4 分块查找

分块查找也叫索引顺序查找。

结构：

- 块内可以无序。
- 块间必须有序。
- 建立索引表，保存每块最大关键字和起始位置。

过程：

1. 在索引表中确定目标可能所在的块。
2. 在对应块内顺序查找。

如果块数和块内元素数比较均衡，平均效率接近：

```text
O(sqrt(n))
```

分块查找结合了顺序查找和折半查找的思想。

## 7.5 二叉排序树

二叉排序树简称 BST。

性质：

- 左子树所有结点关键字小于根。
- 右子树所有结点关键字大于根。
- 左右子树也是二叉排序树。

中序遍历可以得到递增序列。

### 查找

从根开始：

1. 目标等于当前结点，查找成功。
2. 目标小于当前结点，进入左子树。
3. 目标大于当前结点，进入右子树。

时间复杂度取决于树高：

- 最好接近 `O(log n)`。
- 最坏退化为链表，`O(n)`。

### 插入

从根开始查找。

查找失败的位置就是新结点插入位置。

新插入结点一定是叶子结点。

### 删除

分三种情况：

1. 删除叶子结点：直接删除。
2. 只有一个孩子：用孩子替代被删除结点。
3. 有两个孩子：
   - 用中序前驱替代。
   - 或用中序后继替代。
   - 再删除原来的前驱或后继结点。

## 7.6 平衡二叉树

平衡二叉树也叫 AVL 树。

要求：

> 任意结点左右子树高度差的绝对值不超过 `1`。

平衡因子：

```text
BF = 左子树高度 - 右子树高度
```

AVL 树中平衡因子只能取：

```text
-1、0、1
```

### 四种失衡

- LL：右单旋。
- RR：左单旋。
- LR：先左旋，再右旋。
- RL：先右旋，再左旋。

### AVL 树高度和最少结点数

高度为 `h` 的 AVL 树最少结点数：

```text
N(h) = N(h - 1) + N(h - 2) + 1
N(0) = 0
N(1) = 1
```

### 删除

删除后可能引起连锁失衡，需要从删除位置向上逐层检查并调整。

## 7.7 红黑树

红黑树是近似平衡的二叉排序树。

常见性质：

1. 每个结点是红色或黑色。
2. 根结点是黑色。
3. 叶子空结点视为黑色。
4. 红色结点的孩子不能是红色。
5. 从任一结点到其所有叶子的路径上，黑结点数量相同。

由性质可得：

> 最长路径不超过最短路径的 `2` 倍。

因此红黑树的查找、插入和删除都是：

```text
O(log n)
```

### 插入

先按普通二叉排序树插入，并把新结点置为红色。

如果破坏红黑性质，需要进行：

- 变色。
- 左旋。
- 右旋。

调整方式根据叔叔结点颜色和结点位置判断。

### 删除

删除后可能破坏黑高，需要：

- 向兄弟结点借。
- 变色。
- 旋转。

课程重点通常是红黑树性质、插入调整和黑高。

## 7.8 B 树

B 树是多路平衡查找树。

`m` 阶 B 树性质：

1. 每个结点最多有 `m` 棵子树。
2. 每个结点最多有 `m - 1` 个关键字。
3. 根结点若非叶子，至少有 `2` 棵子树。
4. 其他非叶结点至少有 `ceil(m / 2)` 棵子树。
5. 其他非叶结点至少有 `ceil(m / 2) - 1` 个关键字。
6. 所有叶结点位于同一层。

### 插入

1. 插入到最底层非叶结点。
2. 如果关键字数量超过上限，则分裂。
3. 中间关键字上升。
4. 分裂可能向上传播。

### 删除

1. 如果关键字在非叶结点，用前驱或后继替代。
2. 删除底层关键字。
3. 如果关键字数量不足：
   - 向兄弟借。
   - 或与兄弟合并。
4. 合并可能向上传播。

## 7.9 B+ 树

B+ 树常用于数据库和文件系统索引。

与 B 树的区别：

- 非叶结点只保存索引，不直接保存记录。
- 所有记录关键字都出现在叶结点。
- 叶结点按顺序链接。
- 更适合范围查询和顺序扫描。

B+ 树通常有：

- 分支结点。
- 叶结点。

叶结点保存数据或数据指针。

## 7.10 散列查找

散列表通过散列函数把关键字映射到存储地址。

```text
H(key) = 地址
```

理想情况下查找为：

```text
O(1)
```

但必须处理冲突。

### 常见散列函数

- 直接定址法。
- 除留余数法。
- 数字分析法。
- 平方取中法。
- 折叠法。
- 随机数法。

除留余数法：

```text
H(key) = key % p
```

`p` 通常取不大于表长的最大质数。

### 冲突处理

#### 拉链法

- 每个地址维护一个链表。
- 同义词放入同一链表。
- 删除方便。
- 适合冲突较多的场景。

#### 开放定址法

- 线性探测。
- 平方探测。
- 双散列。
- 伪随机序列探测。

线性探测容易产生聚集。

开放定址法删除元素时不能直接把位置置空，应使用删除标记。

### 装填因子

```text
alpha = 表中记录数 / 表长
```

`alpha` 越大，冲突越严重。

散列查找性能主要取决于：

- 散列函数是否均匀。
- 冲突处理方法。
- 装填因子。

## 本章结论

- 顺序查找时间复杂度为 `O(n)`。
- 折半查找要求顺序存储且有序，时间复杂度 `O(log n)`。
- 分块查找结合索引表和块内查找。
- 二叉排序树效率取决于树高。
- AVL 树保持严格平衡。
- 红黑树是近似平衡树，操作复杂度 `O(log n)`。
- B 树适合磁盘索引，B+ 树更适合范围查询。
- 散列表平均查找效率高，但必须处理冲突。
- 开放定址法删除时必须使用删除标记。
