# 第 1 章 绪论
## 1.1 数据结构的基本概念
### 数据
数据是信息的载体，是描述客观事物的数字、字符等符号的集合，也是能够输入到计算机中并被程序识别和处理的符号集合。
从计算机的角度看，最终处理的是二进制中的 `0` 和 `1`。现实世界中的信息只要存在确定的转换规则，都可以转换为二进制形式。

### 数据元素和数据项

- 数据元素：数据的基本单位，通常作为一个整体处理。
- 数据项：组成数据元素的最小单位。
- 组合项：由若干数据项组合成的一个整体信息。
一个信息到底算数据元素还是数据项，取决于具体业务需求。

### 数据结构和数据对象

- 数据结构：相互之间存在一种或多种特定关系的数据元素的集合。
- 数据对象：具有相同性质的数据元素的集合。

二者的区别是：

- 数据结构强调数据元素之间的关系。
- 数据对象强调数据元素性质相同，不强调元素之间的关系。

例如，同一个门店排队的顾客之间存在先后关系，因此这些数据元素构成一个数据结构。不同门店的排队顾客性质相同，可以看作同一个数据对象中的元素。

## 1.2 数据结构的三要素

学习任何数据结构，都要关注三个方面：

1. 逻辑结构。
2. 物理结构，也叫存储结构。
3. 数据的运算。

### 逻辑结构

逻辑结构描述数据元素之间的抽象关系，与具体存储方式无关。

常见逻辑结构包括：

#### 集合结构

数据元素同属于一个集合，除此之外没有其他关系。

#### 线性结构

数据元素之间是一对一关系。

- 除第一个元素外，每个元素都有唯一前驱。
- 除最后一个元素外，每个元素都有唯一后继。

常见例子：

- 排行榜。
- 餐厅排号队列。
- 烤串上的食物。

#### 树形结构

数据元素之间是一对多关系。

常见例子：

- 思维导图。
- 计算机中的文件夹和文件。
- 自然界中的树。

#### 图状结构

也叫网状结构，数据元素之间是多对多关系。

常见例子：

- 不同地点之间的道路。
- 微信或微博用户之间的好友关系。

图状结构中，可以把用户看作顶点，把好友关系看作边。删除好友关系可以理解为删除两个顶点之间的一条边。


### 存储结构

存储结构要解决的问题是：

> 如何用计算机表示数据元素之间的逻辑关系？

常见存储结构包括：

#### 顺序存储

逻辑上相邻的数据元素，在物理内存中也相邻存放。

特点：

- 需要一片连续存储空间。
- 逻辑相邻关系由物理位置直接体现。

用传统排队举例：顾客在物理空间中连续排列。

#### 链式存储

逻辑上相邻的数据元素，在物理内存中不一定相邻。

元素之间通过指针连接，指针表示后继元素所在的位置。

> 学习数据结构前，应当先掌握 C 语言中与指针有关的内容。

#### 索引存储

建立索引表，记录数据元素的关键字和实际存储地址。

关键字是能够区分不同数据元素的数据项。例如，每个人的身份证号可以作为关键字。

#### 散列存储

根据关键字直接计算数据元素的存储地址，也叫哈希存储。

散列存储的具体原理会在后续查找章节中学习。

除顺序存储外，其他存储结构通常可以统称为非顺序存储。

### 存储结构的影响

不同存储结构会影响：

1. 存储空间分配的方便程度。
2. 数据运算的实现方式和速度。

- 顺序存储插入元素时，后面的元素可能需要整体后移。
- 链式存储插入元素时，只需要修改指针。
- 顺序存储可以通过位置直接找到第 `i` 个元素。
- 非顺序存储查找第 `i` 个元素通常没有这么直接。

因此：

- 运算的定义通常针对逻辑结构。
- 运算的具体实现针对存储结构。

### 数据类型和抽象数据类型

数据类型可以理解为：

> 一个值的集合，以及定义在这个集合上的一组操作的总称。

例如：

- 布尔类型只能取真、假两个值，可以执行与、或、非等操作。
- `int` 类型有固定取值范围，可以执行加减乘除和取模等操作。

数据类型可以分为：

- 原子类型：值不能再分解，例如布尔类型、整数类型。
- 结构类型：值可以继续分解为若干分量，例如 C 语言中的结构体。

抽象数据类型简称 ADT。

抽象数据类型用数学化语言描述数据的逻辑结构和操作，不关心具体存储结构。只有真正实现时，才需要考虑顺序存储、链式存储等物理结构。

## 1.3 算法的基本概念

程序 = 数据结构 + 算法

数据结构负责描述现实问题，算法负责高效处理数据。

### 算法的定义

算法是对特定问题求解步骤的一种描述，是一组有限指令，每条指令表示一个或多个操作。

用“番茄炒蛋”解释：

- 食材相当于数据结构。
- 洗、切、打蛋、翻炒等步骤相当于算法。
- 最终做好的菜相当于算法结果。

### 算法必须具备的五个特性

#### 有穷性

算法必须在执行有限步骤后结束，每一步也能在有限时间内完成。

算法和程序的区别：

- 算法必须有穷。
- 程序可以长期甚至无限运行。

例如，微信是一个程序，但通常不能称为算法，因为只要用户不关闭，它就可能持续运行。

死循环不具备有穷性，因此不是算法。

#### 确定性

算法中每条指令必须有明确含义。

对于相同输入，只能得到相同输出。

用年龄排序举例：

- 如果两个人年龄相同，没有规定谁在前谁在后，就可能得到两种结果。
- 因此这种描述存在歧义。

可以补充规则：

> 年龄相同时，原先在前的元素仍然排在前面。

这样相同输入就一定有相同输出。

#### 可行性

算法中的操作必须能够通过计算机程序实现。

#### 输入

算法可以有零个或多个输入。

输入来自某个特定对象的集合，这个集合叫数据对象。

#### 输出

算法必须有一个或多个输出。

算法可以有零个输入，但不能没有任何输出。

这五个特性必须同时满足。只要有一个不满足，就不能称为算法。

### 好算法的评价标准

一个算法满足基本特性以后，还应当追求：

1. 正确性：能够正确解决问题。
2. 可读性：别人和自己以后都能看懂，关键位置应写注释。
3. 健壮性：输入非法数据时能做出合理反应，而不是继续产生错误结果。
4. 高效率：执行时间尽可能少，对应低时间复杂度。
5. 低存储需求：运行时占用内存尽可能少，对应低空间复杂度。

## 1.4 时间复杂度

### 为什么不能只靠实际运行时间

直接运行程序统计时间存在问题：

- 机器性能不同。
- 编程语言不同。
- 编译程序生成的机器指令质量不同。
- 某些算法不能先实际运行再说，例如导弹轨迹控制。

因此，需要在算法运行前估计：

> 算法的执行时间 `T` 与问题规模 `n` 之间的关系。

### 基本统计方法

分析时先做简化：

> 默认执行任意一行代码所花的时间相同。

然后统计每行代码执行次数。

例如，循环执行 `n` 次：

- 循环体中的语句执行 `n` 次。
- 循环条件的判断可能执行 `n + 1` 次。
- 顺序执行的代码执行常数次。

由此得到执行次数与 `n` 的关系。

### 大 O 表示法

当 `n` 足够大时，低阶项和常数系数对增长趋势影响很小，因此只保留最高阶项，并把系数化为 `1`。

例如：

```text
T(n) = 3n + 3
```

可以表示为：

```text
T(n) = O(n)
```

常用规则：

- 加法规则：多项相加时，只保留最高阶项。
- 乘法规则：两个复杂度相乘时，将对应复杂度合并。

### 常见复杂度增长速度

```text
O(1) < O(log n) < O(n) < O(n log n)
     < O(n^2) < O(n^3) < O(2^n) < O(n!)
```

> 常对幂指阶

含义是：

- 常数级。
- 对数级。
- 幂函数级。
- 指数级。
- 阶乘级。

从左到右，增长速度越来越快。

### 分析代码的实用方法

顺序执行、不带循环的大量代码只会增加常数项，不影响数量级。

因此：

- 不需要逐行统计所有顺序代码。
- 重点分析循环。
- 循环中选一条基本操作，分析它与 `n` 的关系。
- 多层嵌套循环要找到最深层语句的总执行次数。

常见例子：

- 单层循环执行 `n` 次：`O(n)`。
- 双重循环各执行 `n` 次：`O(n^2)`。
- 每次规模减半：`O(log n)`。
- 循环变量每次乘 2：也是对数复杂度。

## 1.5 空间复杂度

空间复杂度衡量：

> 算法运行时所需内存空间与问题规模 `n` 之间的关系。

只关注额外的、与问题规模相关的空间，不需要精确计算每个类型占几个字节。

### 普通程序的空间复杂度

- 只使用常数个变量：`O(1)`。
- 定义长度为 `n` 的一维数组：`O(n)`。
- 定义 `n × n` 的二维数组：`O(n^2)`。
- 同时定义 `n × n` 数组和长度为 `n` 的数组：保留最高阶，即 `O(n^2)`。

能够只使用常数空间完成工作的算法，也可以称为原地工作。

### 递归调用的空间复杂度

递归调用时，每一层调用都要保存：

- 参数。
- 局部变量。
- 返回地址等运行信息。

如果每一层占用常数空间，递归深度为 `n`，则空间复杂度通常是：

```text
O(n)
```

> 大多数考试题目中，递归算法的空间复杂度等于递归调用深度。

如果每一层额外定义的空间与当前参数有关，则需要逐层累加。

例如，第一层长度 `n`，第二层长度 `n - 1`，一直递减到 `1`，总空间近似为：

```text
n + (n - 1) + ... + 1 = n(n + 1) / 2
```

此时空间复杂度为：

```text
O(n^2)
```

### 本章结论

- 数据结构研究现实问题的信息化，以及如何高效处理信息。
- 数据结构的三要素是逻辑结构、存储结构和数据运算。
- 逻辑结构包括集合、线性、树形和图状结构。
- 存储结构包括顺序、链式、索引和散列存储。
- 算法必须具有有穷性、确定性、可行性、输入和输出。
- 好算法还要追求正确性、可读性、健壮性、高效率和低存储需求。
- 时间复杂度关注执行时间与问题规模的增长关系。
- 空间复杂度关注额外空间与问题规模的增长关系。
- 递归算法的空间开销通常与递归深度有关。
